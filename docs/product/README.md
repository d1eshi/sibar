# Product Pillars

Use these pillars to reject or accept work for v0.1.

## 1. Artifact Before Course

The user learns from a real software artifact, not from a generic lesson.

The artifact may be generated by an agent or imported from an existing repo.

## 2. Attempt Before Explanation

Sibi asks the user to predict, explain, trace, or modify before giving the answer.

Fast explanation is allowed only after the user has produced evidence of their current model.

## 3. Understanding Memory, Not Chat Memory

Sibi remembers concepts, answers, gaps, repairs, challenges, and readiness.

It does not treat chat history as comprehension.

## 4. Gaps Are Evidence

Declared uncertainty and wrong answers are useful product signals.

They are not failures, grades, or shame points.

## 5. Readiness Over Output

Sibi is successful when it can say what the user is ready to inspect, explain, modify, or own.

The goal is durable technical ownership, not more generated code.
