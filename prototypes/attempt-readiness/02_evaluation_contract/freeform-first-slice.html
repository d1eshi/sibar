Evaluator Logic Trace

How the freeform evaluator classifies each answer shape without reading answer_class. The evaluator sees only user_answer text, declared_confidence, and repo evidence matching.

Step 1 — Check false confidence
If declared_confidence == "high" or answer contains "certain" AND answer contains "all files under the repo root" or "excluded paths do not matter" → false_confidence_gap
Matches: GC-006
Step 2 — Check design-induced confusion
If answer contains "style document" or "not an enforcement rule" AND contains "excluded" or mentions "docs" → design_induced_gap
Matches: GC-008
Step 3 — Check partial / flow gap
If answer contains "mixed" or "cannot explain" or "full sequence" → flow_gap
Matches: GC-003
Else:
Step 4 — Check repo citation
If answer does NOT mention any required repo path by substring → evidence_gap
Matches: GC-002
Step 5 — Otherwise: readiness
Answer mentions required paths and no contradictions detected → readiness (bounded to "ready to modify with guardrails")
Matches: GC-001
🛡
Hard-rule enforcement
If a gap or readiness finding would be emitted without user evidence or repo evidence, the evaluator throws instead of producing an invalid finding.

Known Weaknesses (from spec + verifier)

Substring-only citation detection
Citations are detected by answer.includes(path). A correct answer that uses a basename, a different relative prefix, or a markdown link will be misclassified as evidence_gap.
Fixed readiness label
All readiness findings emit "ready to modify with guardrails", ignoring the mastery check's minimum_readiness. May over-declare for checks that expect only "ready to inspect".
Shallow repo excerpts
Repo evidence excerpts are the first line matching boundary keywords or the first non-empty line. Meaningful but shallow — not semantic code context.
First-slice scope only
The evaluator covers only 5 of 40 gold cases (artifact_boundary trace). Other concepts/operations are not yet validated.
